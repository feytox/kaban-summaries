# L04. Системы хостинга

**Хостинг** - доставка кода на вычислительные мощности, публикация его пользователям и возможность наблюдать за приложением и управлять им. ([02:46](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=166))

Приложение проходит путь: процесс изолируют в контейнер, запускают в нескольких репликах ради отказоустойчивости и масштабирования, а набор сервисов разного назначения образует кластер. Следующий вопрос - как пережить смерть сервера и быстро размножать кластеры. ([04:39](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=279))

## Виртуализация и контейнеризация

Обе технологии развивались параллельно и решают разные задачи, поэтому в итоге контейнеры крутят на виртуальных машинах. ([14:43](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=883))

|        | Виртуализация                                        | Контейнеризация                           |
| ------ | ---------------------------------------------------- | ----------------------------------------- |
| Задача | нарезать большой сервер, запустить чужую архитектуру | изолировать процессы в пределах одной ОС  |
| Ядро   | гостевое, гипервизор транслирует его вызовы          | общее с хостом                            |
| Плюс   | гостевая ОС может отличаться от хостовой             | нет прослойки, железо утилизируется лучше |
| Минус  | накладные расходы гипервизора                        | одно ядро и одна архитектура на всех      |

([11:53](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=713))

Изоляция контейнеров - не гарантия, а скорее обещание хостинга. ([19:09](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=1149))
- cgroups ограничивают не ядра, а долю процессорного времени; троттлинг включается не сразу, и жадный процесс успевает помешать соседям.
- В namespaces время от времени находят уязвимости ядра, через которые процесс видит чужие процессы. ([21:07](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=1267))
- Windows-контейнеры требуют ту же сборку Windows, что на хосте, и после обновления хоста образы пересобирают; в проде они не прижились. ([17:40](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=1060))

## Контейнер - не только Docker

**Контейнер** - способ запустить приложение с изоляцией на уровне ядра по namespaces и системным ресурсам; Docker лишь пользовательский интерфейс к нему, как руль и педали к шасси. ([28:42](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=1722))

| Уровень  | Примеры                | Что делает                                                            |
| -------- | ---------------------- | --------------------------------------------------------------------- |
| Клиенты  | Docker, Podman         | сборка образа, пуш в registry, сеть и тома для контейнеров            |
| Рантаймы | containerd, CRI-O, LXC | объясняют ядру, как поднять и изолировать процесс, настроить iptables |

([25:14](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=1514))
- На нодах Kubernetes Docker обычно нет: хостинг только запускает контейнеры, а образы собирают на десктопе или в CI. ([27:49](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=1669))

## Зачем оркестратор

[[devops-L03-dive-хранение-compose#Docker Compose|Docker Compose]] описывает контейнеры в пределах одной машины. Когда сервер падает, кто-то должен перенести файлы на другую ноду и выполнить `docker compose up`; оркестратор делает это автоматически. ([33:13](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=1993))

- **Docker Swarm** объединяет несколько Docker-хостов в кластер; его можно развернуть за вечер, и по числу инсталляций он, по мнению лектора, обгоняет Kubernetes. ([34:24](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=2064))
- Swarm выбирают, где нужна жёсткая изоляция на VM и нет людей для Kubernetes, например в банках; в Контуре Kubernetes поддерживает команда из 5+ человек. ([38:02](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=2282))
- Kubernetes - не готовый хостинг, а платформа: компании строят на ней свои системы через расширение API (**CRD**, custom resource definition). ([39:37](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=2377))
	- в Контуре аннотации в манифесте деплоя сами создают алерты в мониторинге

## Kubernetes: желаемое состояние

В Kubernetes декларативно описывают желаемое состояние ("3 реплики приложения"), и он постоянно сверяет его с действительным. В отличие от Ansible, который отработал и завершился, Kubernetes исправляет расхождения всё время. ([43:24](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=2604))

| Компонент          | Где           | Роль                                                      |
| ------------------ | ------------- | --------------------------------------------------------- |
| kube-apiserver     | control plane | HTTP API, с ним работают `kubectl` и остальные компоненты |
| etcd               | control plane | хранилище желаемого состояния                             |
| scheduler          | control plane | выбирает ноду для пода                                    |
| controller-manager | control plane | следит за порядком в кластере                             |
| kubelet            | каждая нода   | запускает поды через рантайм, настраивает iptables        |
| kube-proxy         | каждая нода   | связь подов на разных нодах                               |

([44:16](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=2656))

Kubernetes размещает реплики, обновляет их и настраивает сеть, но не деплоит, не мониторит и не отвечает за корректность приложения: пока процесс не вышел с ненулевым кодом, под для него работает. Деплоят отдельными инструментами вроде Helm. ([48:48](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=2928))

## Pod и реплики

**Pod** - минимальная единица хостинга в Kubernetes: свой IP, контейнеры внутри общаются через localhost, всегда на одном сервере и могут делить том. ([54:58](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=3298))

В один под кладут неразделимые контейнеры, например Postgres и экспортёр его метрик; такой вспомогательный контейнер называют **sidecar**. Обычно под - один контейнер, а реплика приложения и под - одно и то же. ([57:12](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=3432))

**ReplicaSet** следит, чтобы подов было заданное в Deployment число, и при гибели сервера ищет, где поднять замену. ([1:00:50](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=3650))

- Под проходит Pending (kubelet пулит образ из registry) и Ready; по умолчанию Ready значит лишь, что процесс не завершился, поэтому здоровье проверяют пробы liveness и readiness. ([1:09:19](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=4159))
- По лектору, при ненулевом коде выхода любого контейнера перезапускается весь под, а отдельный контейнер перезапускается сам, без участия Kubernetes. ([1:11:12](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=4272))
	- по документации контейнеры пода перезапускает kubelet по `restartPolicy`, сам под не пересоздаётся ([Kubernetes docs](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/#container-restarts)) (вне конспекта)
- Растущий счётчик рестартов при статусе Running (например, приложение не влезает в кучу и его убивает OOM killer) - повод для алерта. ([1:13:10](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=4390))
- Для отказоустойчивости хватает 2 реплик, под нагрузку их число меняет **HPA** (horizontal pod autoscaler) по CPU в заданных пределах. ([1:19:13](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=4753))

## Canary

**Canary-релиз** - выкатка новой версии сначала на часть реплик с проверкой, что они живы; rolling update лектор считает его частным случаем. ([1:21:27](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=4887))
- Порцию обновляемых реплик выбирают так, чтобы на неё шло заметное число запросов: из 1000 реплик одна ничего не покажет.
- Здоровье проверяют хэлсчеки приложения: при ответе не 200 Helm откатывает реплики к прошлой версии с её конфигами и секретами, а сломанная реплика не получает трафик. ([1:23:40](https://fiit.ktalk.ru/recordings/o6nhS2Und73uVOzFVEaC?t=5020))
