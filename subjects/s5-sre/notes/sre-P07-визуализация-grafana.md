# P07. Визуализация: Grafana

Конфиг data source и команды Helm восстановлены по рассказу семинариста.

## Дашборд как приборная панель

По одному графику в vmui состояние сервиса после алерта не понять: решение принимают по нескольким понятным графикам на одном экране. ([02:49](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=169))

Эталон дашборда - приборная панель автомобиля: на ней всё нужное для решения и ничего лишнего, громкость музыки водителю не нужна. Хороший дашборд: ([05:30](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=330))
- не избыточен
- информативен
- быстро изучается
- компактен: всё видно одним взглядом

Альтернативы Grafana заточены под анализ данных, а не под оперативный мониторинг: ([06:59](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=419))

| Инструмент      | Назначение                          |
| --------------- | ----------------------------------- |

От BI её отличают обновление в реальном времени (в инцидент нужно состояние сейчас) и интерактивность: фильтры, переменные, выбор интервала. ## Тип панели под задачу

**Панель** - окно с одной визуализацией. **Дашборд** - одна или несколько панелей, которые вместе показывают состояние чего-то: сервиса, Postgres. ([11:24](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=684))

Все типы запоминать не нужно: важно знать, какой подходит для текущего значения, истории или распределения. ([16:43](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1003))

| Тип         | Что показывает                               | Пример задачи                               |
| ----------- | -------------------------------------------- | ------------------------------------------- |
| Stat        | одно крупное значение: текущее или сумма     | жив ли сервис, текущий RPS, CPU по серверам |
| Gauge       | значение на шкале с цветными порогами        | насколько задержка далека от нормы          |
| Bar gauge   | несколько значений-столбиков с порогами      | сравнить занятость дисков                   |
| Time series | зависимость значения от времени              | RPS, задержки, ошибки, утилизация           |
| Heatmap     | распределение значений по времени и величине | задержки по бакетам гистограммы             |
| Statusmap   | состояние множества объектов во времени      | был ли под запущен в каждый момент          |
| Polystat    | много значений-плиток с цветом по порогу     | состояние набора сервисов                   |
| Pie chart   | доли от целого                               | ошибки по статус-кодам, запросы по методам  |

- Stat показывает последний момент, а не историю: хорош для верхнего уровня дашборда
- Gauge читается без цифр: зелёный - норма, жёлтый - ещё терпимо, красный - критично
- Heatmap обычно рисует [[sre-P04-логи-и-метрики#Метрики|гистограмму]]
- Polystat по семинаристу самая редкая, на практике он её почти не видел
- Statusmap и Polystat - плагины; встроенные аналоги Statusmap - State timeline и Status history (вне конспекта, [документация](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/))

## Drill-down

**Drill-down** - подход, при котором дашборд сначала даёт общую картину (в норме или нет), а затем детализирует шаг за шагом до инстанса или запроса. Задача - пройти путь клиента и быстро найти шаг, где появляются ошибки. ([17:36](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1056))

На слайде сверху Stat с процентом ошибок по эндпоинтам, ниже Time series по CPU и задержке. Раскладка сверху вниз из [[sre-P04-логи-и-метрики#Дашборды|P04]] - тот же подход. ([18:20](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1100))

Drill-down продолжается между дашбордами через ссылки: с общего дашборда бизнес-услуг продукта по красному сервису переходят на его дашборд. ([29:37](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1777))

## Понятный без автора

Дашборд читают другие инженеры и через месяцы, поэтому значения и события на нём должны объяснять себя сами: ([19:21](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1161))
- единица измерения: Grafana переводит unix-время, байты и доли в читаемый вид
- ссылки на документацию и runbook прямо на панели
- часовой пояс: по умолчанию системный пояс зрителя, при необходимости задаётся жёстко
- логарифмическая шкала: для больших и часто меняющихся чисел видно порядок
- порог (threshold): линия, за которую значение не должно уходить, например 80% CPU

**Аннотация** - метка события на графике: деплой, изменение инфраструктуры, старт рекламной кампании, сбой соседнего сервиса. Она объясняет скачок метрики: RPS вырос, а на метке "старт рекламной кампании". ([23:55](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1435))
- по семинаристу аннотацию добавляют вручную, кликом по точке графика
- её также создают через HTTP API (вне конспекта, [документация](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/annotate-visualizations/))

## Один дашборд на много объектов

**Переменная** - значение, которое подставляется в запросы панелей вместо хардкода и фильтрует дашборд. Почти в любом реальном дашборде переменные делят данные по системам (БД, балансеры, приложения), окружениям, продуктам и узлам. ([23:02](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1382))

```promql
# переменная instance: значения лейбла из метрики, отфильтрованные уже выбранными env и service (слайд)
label_values(node_uname_info{env=~"$env", service=~"$service"}, instance)
```

**Строка (row)** - сворачиваемая группа панелей по смыслу: SLI/SLO, ресурсы, бизнес-метрики. ([28:00](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1680))

**Повтор** - панель или строка, нарисованная один раз и размноженная по значениям переменной: например, CPU отдельно для dev, test, stage и prod. ([28:44](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1724))

**Тег** - метка дашборда для поиска среди сотен дашбордов в папках; на визуализацию не влияет. ([27:16](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1636))

## Готовые дашборды и Dashboard as Code

Под популярные экспортеры уже есть готовые дашборды, поэтому для типовых систем вроде Postgres или Redis свои не рисуют, а импортируют. ([45:25](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=2725))

**Data source** - абстракция источника данных в Grafana: VictoriaMetrics, Postgres, MySQL, ClickHouse и другие; под отсутствующий можно написать свой. ([39:10](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=2350))

```yaml
# values для Helm-чарта Grafana: VictoriaMetrics как источник по умолчанию
datasources:
  datasources.yaml:
    apiVersion: 1
    datasources:
      - name: VictoriaMetrics
        type: prometheus                  # VictoriaMetrics совместима с Prometheus
        url: http://<сервис-victoria-metrics>:8428
        isDefault: true                   # подставляется в новые панели
```

Любой дашборд Grafana - это JSON: готовый скачивают с grafana.com, импортируют, и панели сразу заполняются метриками. ([46:12](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=2772))

**Dashboard as Code** - генерация JSON дашборда кодом через библиотеки под разные языки (на слайде Kotlin DSL) с хранением в git. ([30:52](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1852))
- плюс: версионирование дашбордов
- плюс: дашборды переживут сбой базы Grafana
- минус: нет единого стандарта, каждая команда выбирает свой инструмент

Семинарист сам Dashboard as Code не использовал и не встречал: дашборды обычно рисуют в UI. В [[sre-P04-логи-и-метрики#Дашборды|P04]] код советовали ради быстрого восстановления мониторинга. ([32:30](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=1950))

## Helm

**Helm** - пакетный менеджер Kubernetes: шаблонизирует манифесты, а готовые чарты разворачивают систему одной командой. Состояние релиза Helm хранит в Secret кластера, поэтому можно откатиться. ([36:37](https://tbank.ktalk.ru/recordings/8tJQcEX253EiTjSYWREt?t=2197))

```bash
helm install grafana <чарт> -f grafana-values.yaml   # установить чарт со своими values
helm list -n monitoring                               # что установлено в namespace
helm rollback grafana                                 # приложение запустилось, но нашли баг: вернуть предыдущую версию
```
