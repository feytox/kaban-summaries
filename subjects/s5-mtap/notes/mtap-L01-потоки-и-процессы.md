# L01. Потоки, процессы, планировщик

Код восстановлен по демо лектора и мог выглядеть на экране иначе.

## Позиция лектора

Многопоточность - оптимизационная задача без одного правильного ответа. Любой выигрыш в скорости оплачивается сложностью и риском, и решать, чем пожертвовать, должен инженер, а не ИИ. ([36:02](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=2162))

Ошибки в многопоточном коде - это не исключение в логах, а зависания и частичная потеря данных. Их расследуют по косвенным признакам и гипотезам, и ИИ пока справляется с таким кодом плохо. ([37:49](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=2269))

Многопоточный код проектируют заранее: как потоки делят память, как передают данные, что будет при сбое. ([42:48](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=2568))

## Термины

**Многопоточность** (multithreading) - подход, при котором задачи выполняют разные потоки. ([46:08](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=2768))

**Конкурентность** (concurrency) - борьба за ограниченный ресурс, например за один процессор. Она возникает при многопоточности, но это отдельное понятие. ([46:46](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=2806))

**Параллелизм** - одновременное выполнение задач. Если два врача принимают из одной очереди, но не одновременно, это многопоточность без параллелизма. [?] Лектор не пояснил, почему два врача с одной очередью не принимают одновременно. ([47:30](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=2850))

**Асинхронность** - выполнение не по порядку: задачу делегируют и потом ждут результат. Подробно её разберут в середине семестра. ([50:24](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=3024))

Python - пример многопоточности без параллелизма: ([48:14](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=2894))
- потоки есть, но GIL пускает к интерпретатору только один поток за раз
- поэтому настоящего параллелизма и ускорения нет
- есть экспериментальная сборка без GIL

**Процесс** - экземпляр программы. Одну программу можно запустить несколькими процессами, например два окна блокнота. ([51:51](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=3111))

**Поток** - базовая единица исполнения внутри процесса. У одного процесса может быть несколько потоков.

## Планировщик и кванты

На одном ядре несколько задач работают за счёт прерываний: планировщик выдаёт им кванты времени. ([53:24](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=3204))
- ОС раздаёт кванты процессам
- программа может сама раздавать кванты своим потокам; по лектору, .NET так делает (см. поправку ниже)
- планировщик учитывает приоритеты: кому-то кванты нужнее
- квант может закончиться раньше срока: процесс вернул его сам или планировщик отобрал, увидев проблему ([01:06:25](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=3985))

Одно ядро встречается часто: Kubernetes нередко выдаёт контейнеру одно ядро. Многопоточная программа там работает, но почти ничего не выигрывает. ([54:04](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=3244))

| Многозадачность | Кто отдаёт квант                 | Риск                                                     |
| --------------- | -------------------------------- | -------------------------------------------------------- |
| Вытесняющая     | планировщик отбирает его сам     | -                                                        |
| Кооперативная   | поток отдаёт сам, когда закончил | поток из-за бага или нагрузки не отдаст квант, все стоят |

ОС общего назначения используют вытесняющую многозадачность, чтобы системным процессам вроде курсора мыши всегда хватало квантов. Кооперативная, по лектору, встречается в ОС реального времени. ([56:20](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=3380)) Типичная RTOS вытесняет задачи по приоритету, а кооперативное планирование в них лишь один из вариантов (вне конспекта, [Wikipedia](https://en.wikipedia.org/wiki/Real-time_operating_system#Scheduling)).

**Переключение контекста** (context switch) - сохранение состояния потока (номер инструкции, память), чтобы потом продолжить с того же места. ([59:22](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=3562))

Переключение контекста - плата за многопоточность. Если потоков много, а ядер мало, переключения могут съесть всё время, и полезной работы не останется.

Приоритеты процессов меняют поведение планировщика: ([01:03:55](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=3835))
- realtime: обычно служебные процессы
- normal: обычные программы
- idle: самый низкий, например для фоновой чистки
- приоритет можно поменять в диспетчере задач

## C#: Process и Thread

```csharp
var child = Process.Start("notepad.exe");          // дочерний процесс
child.WaitForExit();

var current = Process.GetCurrentProcess();
current.ProcessorAffinity = (IntPtr)0b0001_0100;   // только ядра 2 и 4 (счёт с 0)
current.PriorityClass = ProcessPriorityClass.High;
```

([01:07:26](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=4046))

- `ProcessorAffinity` - битовая маска ядер, на которых процесс может работать.
	- пример: программа под "запросом смерти" съела все ядра, её прибивают к одному ядру
	- то же можно сделать в диспетчере задач
- `PriorityClass` - приоритет у планировщика. Realtime вместе с неудачным кодом может подвесить систему до перезагрузки.

```csharp
var thread = new Thread(DoWork) { IsBackground = true };
thread.Start();
thread.Join();

Task.Run(DoWork);   // так пишут сейчас: смысл тот же, устройство другое
```

- `IsBackground` решает, ждёт ли программа этот поток при выходе (подробнее в [[mtap-L02-блокирующая-синхронизация#Правила|L02]]).
- По лектору, `Join` обязателен, чтобы вернуть ограниченный ресурс.
	- на деле `Join` только ждёт завершения потока и ничего отдельно не освобождает (вне конспекта, [docs](https://learn.microsoft.com/en-us/dotnet/api/system.threading.thread.join))

По лектору, потоки в C# - кооперативная многозадачность, и квант между ними делит рантайм; он сам тут засомневался. По документации кванты всем потокам .NET выдаёт ОС, и поток с более высоким приоритетом вытесняет остальные (вне конспекта, [docs](https://learn.microsoft.com/en-us/dotnet/standard/threading/scheduling-threads)). ([01:12:48](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=4368))

**Демон** - фоновый поток или процесс, который работает отдельно от основного. ([01:14:03](https://kontur.ktalk.ru/recordings/11GratLi3NeCNdvzV9Lw?t=4443))

**Зомби** - завершившийся дочерний процесс, которого родитель ещё не "забрал" вызовом `wait` (вне конспекта, `man 2 wait`). Лектор описал зомби иначе: как родителя, который ждёт незавершённых детей.
